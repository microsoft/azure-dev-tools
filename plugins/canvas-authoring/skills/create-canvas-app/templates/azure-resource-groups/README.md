# __CANVAS_NAME__

A read-only Azure starter generated by the canvas toolkit companion.
The native host entry is copied unchanged: connect it before building.

## Native hookup

Continue the installed `create-canvas` skill. Add this import to the copied
`src/extension.mjs`:

```js
import { attachToolkit } from "./toolkit.mjs";
```

Wrap the existing native options as `createCanvas(attachToolkit({ ... }))`,
preserving its metadata and surrounding session wiring. The adapter replaces
only scaffold demo callbacks and chains native close after toolkit cleanup.
Custom callbacks or competing shutdown handlers require deliberate integration.
The original scaffold is never modified.

## Build and preview

Node >=22; Node 24 recommended. `package.json` either pins the chosen npm
version or uses the approved archive copied to `vendor/canvas-toolkit.tgz`.
Registry setup is offline; installation must succeed before building, and the
selected toolkit must export `/build`. No source fallback happens automatically.

```sh
npm install
npm run build
npm run smoke
```

Keep the lockfile; use `npm ci` for later installs. `npm run smoke` uses installed
Google Chrome and synthetic data in a sandboxed iframe. Set `CANVAS_BROWSER` to
an explicit Chromium executable if needed. It never logs in or reads live Azure.
`npm test` provides focused domain/server checks when changing those behaviors.
No browser download or global install happens automatically.

Use the host skill to install the **whole `dist/` directory** in the chosen
scope, reload the extension provider, then open its panel. A panel refresh
reloads browser files; it is not a provider restart. The footer and `get_state`
show the provider build ID, and the UI warns if served files have another ID.
Build success and the test SDK seam do not prove native-host activation.

## Real Azure

The default mode is `azure`. Opening is lazy: no CLI/profile read, login or
resource query occurs automatically. With an existing Azure CLI login
(CLI >=2.61), click **Load profile**, select a subscription explicitly, then
click **List resource groups** or invoke the same agent action.

The app never chooses the first/default subscription, changes CLI defaults,
logs in, or writes cloud resources. Successful empty results, failures,
cancelled reads and missing scope are distinct. Lists are bounded at 200 rows
and 10 pages and project only ID, name and location.

For a synthetic walkthrough, open a separate panel with `{"mode":"fixture"}`.
Its banner explicitly labels invented data. Fixture evidence is not proof of
live Azure permissions, network access or native host UI behavior.

## Customize

- `src/domain.mjs`: shared schemas, scope binding, cancellation and stale results.
- `src/resource-groups.mjs`: the small reader copied from the bundled quickstart.
- `src/canvas.mjs`: per-panel ownership, safe transport and public UI assets.
- `src/browser/`: framework-free UI and the toolkit subscription picker.
- `src/toolkit.mjs`: native adapter and shutdown ownership.
- `scripts/build.mjs`: separate Node/browser builds, public asset helper and build ID.

The toolkit build helper preserves asset-owning UI modules and relative files.
Do not replace it with bare bundling: `new URL(..., import.meta.url)` assets are
not automatically copied by esbuild. No SVG source rewriting is used.

State is ephemeral per panel. Closing a panel or restarting the provider clears
its scope/results and cancels work; reloading the browser keeps the open panel.
Start with a display-only location filter, retaining raw IDs and loaded counts.
Cloud writes require a separate authorization and confirmation design.
